01. TITLE: CÁCH KHẮC PHỤC KHI ĐÃ TẠO MERGE REQUEST NHƯNG LEADER CHƯA KỊP XỬ LÝ.
----------------------------------------------------------------------------------------------------------------------------------
01. DESCRIBE: Khắc phục vấn đề khi đã tạo merge request trên gitlab, nhưng chưa được leader merge
	dẫn đến các commit của người khác mới tạo ghi đè lên. Commit hiện tại của mình bị đẩy xuống dưới.
	
##################################################################################################################################
Các Bước Thực Hiện
	* Bước 1: git branch
		- kiểm tra nhánh hiện tại:
			+ nếu là nhánh cá nhân thì đổi qua nhánh chính.
			+ nếu đang là nhánh chính thì tiếp tục bước 2.
		
	* Bước 2: git checkout develop
		- chuyển qua nhánh chính để pull dữ liệu mới nhất về.
		
	* Bước 3: git pull
		- lấy dữ liệu mới nhất từ nhánh chính trên Server về Local.
		
	* Bước 4: git checkout tuandx
		- chuyển qua nhánh cá nhân để tiếp tục thực hiện xử lý.
		
	* Bước 5: git rebase develop
		- đồng bộ commit, dữ liệu mới nhất từ nhánh chính qua nhánh cá nhân.
			+ kết quả: "Successfully rebased and updated refs/heads/tuandx." thì đã thành công
		- nếu có báo lỗi: ví dụ file "ABC.txt"
			+ Bước 5.1: mở file "ABC.txt" sửa lỗi, sau đó cập nhật dữ liệu đúng nhất
			+ Bước 5.2: chạy "git add <ABC.txt>"
			+ Bước 5.3: git rebase develop --continue
			
	* Bước 6: git status
			+ On branch tuandx nothing to commit, working tree clean => đã thành công
	* Bước 7: git push
		- nếu có thông báo "fatal: The current branch tuandx has no upstream branch." 
			{
				Ý nghĩa: Bạn gõ git push trên nhánh tuandx, nhưng nhánh này chưa được liên kết (tracking) 
				với nhánh nào trên server GitLab (origin). Git báo lỗi và hướng dẫn bạn dùng lệnh git push 
				--set-upstream origin tuandx.
			}
			+ nhập lại: "git push --set-upstream origin tuandx"
		- nếu có lỗi " To https://gitlab.ascvn.vn/asc.ems/org/web.git
				! [rejected]            tuandx -> tuandx (non-fast-forward)"
			{
				Ý nghĩa: Bạn làm theo hướng dẫn và chạy lệnh đẩy code kèm thiết lập upstream. 
				Tuy nhiên, Git đã từ chối (rejected) vì nhánh tuandx trên server đang có những thay đổi mới 
				hơn (hoặc khác biệt) so với nhánh trên máy của bạn (máy bạn đang bị "thụt lùi" - behind). 
				Nếu đẩy thẳng lên sẽ làm mất dữ liệu trên server. Git gợi ý bạn nên dùng git pull trước.
			}
			+ nhập lại: "git push --set-upstream origin tuandx --force-with-lease"
				{
					Ý nghĩa: Thay vì dùng git pull để gộp code (có thể gây ra conflict phức tạp mà bạn chưa muốn xử lý lúc đó), 
						bạn đã dùng cờ --force-with-lease kết hợp với --set-upstream.

					Lệnh này có nghĩa là: "Hãy ép buộc đẩy code của tôi lên server để đè lên nhánh tuandx hiện tại, 
						nhưng hãy kiểm tra xem có ai vừa đẩy code lên trước đó không để tránh ghi đè nhầm công sức của người khác".

					Vì an toàn và hợp lệ, Git đã chấp thuận.
				}
	* Bước 8: Lên server GitLab kiểm tra lại merge request đã đúng với ban đầu tạo merge hay chưa.

02. TITLE: CÁCH XÓA 1 COMMIT KHI ĐÃ TẠO
----------------------------------------------------------------------------------------------------------------------------------
02. DESCRIBE: Khi tạo commit Commit_01, tiếp theo tạo thêm 1 commit mới Commit_02.
	Muốn xóa Commit_01 và giữ lại Commit_02
	
##################################################################################################################################
Các Bước Thực Hiện
	* Bước 1: git log --online
		- kiểm tra log hiện tại
		
	* Bước 2: git checkout develop
		- chuyển qua nhánh chính để pull dữ liệu mới nhất về.
		
	* Bước 3: git pull
		- lấy dữ liệu mới nhất từ nhánh chính trên Server về Local.
		
	* Bước 4: git checkout tuandx
		- chuyển qua nhánh cá nhân để tiếp tục thực hiện xử lý.
		
	* Bước 5: git rebase develop
		- đồng bộ commit, dữ liệu mới nhất từ nhánh chính qua nhánh cá nhân.
		
	* Bước 6: git checkout -b "Name_nhanh_moi"
			+ tạo nhánh mới để lưu lại nhánh hiện tại cần xóa, đề phòng cần dùng lại.
		
	* Bước 7: git checkout tuandx
	
	* Bước 8: git log --online
		- kiểm tra lại log
		
	* Bước 9: git rebase -i HEAD~2
		- Git sẽ hiện:
			pick <hash-A> Commit_01
			pick <hash-B> Commit_02
		- Đổi thành:
			drop <hash-A> Commit_01
			pick <hash-B> Commit_02
			
	* Bước 10: git push --force-with-lease origin tuandx
		- Vì bạn rewrite history, cần force push
		
	* Cách này giữ commit Commit_02 như một commit riêng (Git sẽ tạo lại commit Commit_02 với parent mới), 
	còn thay đổi của Commit_01 sẽ bị loại bỏ.

03. TITLE: LẤY LẠI COMMIT SAU KHI ĐÃ PUSH LÊN GITLAB
----------------------------------------------------------------------------------------------------------------------------------
03. DESCRIBE: Khi push Commit lên GitLab, nhưng muốn lấy thông tin Commit về để sửa lại.
	
##################################################################################################################################
Các Bước Thực Hiện
	* Bước 1: git status
		- kiểm tra trạng thái hiện tại
		
	* Bước 2: git checkout tuandx
		- chuyển qua nhánh cá nhân để lấy commit về
		
	* Bước 3: git reset --soft HEAD~1
		- Đưa commit mới nhất quay lại trạng thái chưa commit (Soft Reset)
			+ Dùng lệnh sau để lùi lại 1 commit (giúp code của bạn vẫn được giữ nguyên trong máy, 
			chỉ gỡ bỏ commit vừa push ra khỏi lịch sử tạm thời)
		
	* Bước 4: chỉnh sửa lại thông tin cần thay đổi
		
	* Bước 5: git add .
		- thêm lại các file hợp lệ
		
	* Bước 6: git commit -m "Context"
			+ Tạo lại commit mới
		
	* Bước 7: git push origin tuandx --force-with-lease
		- Lưu ý: Chỉ dùng --force-with-lease khi nhánh đó chỉ có một mình bạn làm việc. 
			Tránh dùng --force thông thường hoặc dùng --force-with-lease nếu nhánh đó đang có người khác 
			cùng collaborate (nếu có người khác cùng làm chung, họ sẽ bị mất sync code).
	
	* Bước 8: git checkout develop
		
	* Bước 9: git pull
			
	* Bước 10: git checkout tuandx
	
	* Bước 11: git rebase develop
	
	* Bước 12: git push origin tuandx --force-with-lease
